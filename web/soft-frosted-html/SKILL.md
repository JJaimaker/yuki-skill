# soft-frosted-html

这套 Skill 以内容逻辑决定版式，再使用柔雾玻璃材质。当前定稿样式是深色 Yuki 研究页。可复用的视觉参数和组件见 [assets/tokens.css](assets/tokens.css)。用户明确指定白底时，改用白色主画布和少量局部光晕，不混用两套底色。

## 先确定内容

1. 阅读原始材料。区分事实、判断、建议和待验证项。
2. 每节只承担一个任务：解释观点、比较差异、呈现关系、展示流程或支持决策。合并重复内容。
3. 每节按“大标题 → 一段不重复的解释 → 内容”展开。除首屏外，桌面端章节标题尽量一行放下。
4. 用文字承担论证，用表格承担精确比较，用图承担关系与流程。只有真实操作入口才使用 Widget。
5. 不用“材料观点”“官方动作”“产品推导”等无意义 Tag 代替说明句。不添加与主题无关的英文眉题、图号或角标。

公开事实和产品推导要写在句子中。不要借视觉效果暗示未经证实的产品成熟度或收益。

## 页面结构

- 桌面画布正文最大宽度约 `1080px`。章节上下留白约 `108px / 115px`。同一信息组保持紧凑；章节之间依靠大留白和细分隔线建立节奏。
- 首屏使用正常内容流。顺序为“主标题 → 解释文案 → 核心内容”。桌面端解释到内容约 `48px`，窄屏约 `28px`。没有视觉主体时，不设置整屏高度。
- 长篇研究页优先用左侧目录。桌面端宽度约 `238px`。目录与画布融为一体。它是一层透亮的暗色玻璃，不是悬浮的独立卡片。目录文字用白色；选中章节使用低透明度的 Gemini 风格多色渐变底纹和细色条，保留白字的可读性。用章节观察器同步当前项。`940px` 以下改为可关闭的抽屉目录，并支持遮罩、Esc 和 `aria-expanded`。
- 关系图、架构图与解释并排时，桌面端图占左侧约三分之二，观点与边界占右侧约三分之一。窄屏按阅读顺序纵向排列。
- 表格优先三列，最多四列。检查列宽和正文断行。窄屏可重排或在容器内横向滚动，不让整页横向溢出。
- 对该用户的研究网页，页脚用“Yuki观测站 · 本次研究内容名称”。居中显示。字号、字重、行高和颜色与“依据与判断边界”标题下的解释文案一致，不放大为第二个标题。

## 字体与文本节奏

- 主标题使用蓝紫柔和渐变。桌面端约 `54–80px`，字重 `800`，行高约 `1.04`；按中文语义断行。窄屏约 `37–47px`，行高约 `1.1`。
- 章节标题桌面端约 `29–39px`，字重 `600`，行高约 `1.28`。正文和章节解释使用 `16px / 1.75`；图注与辅助说明使用 `15px / 1.72`。不要用过浅或过细的字制造轻盈感。
- 主标题、章节标题、解释文案和内容各出现一次。不要再在内容区重复同一结论。英文和数字使用 Inter、Fustat 或系统替代字体；中文优先苹方、思源黑体或 Noto Sans CJK SC。

## 暗色 2.5D 柔雾材质

实施起点见 [assets/tokens.css](assets/tokens.css)。其中的 `.sf-*` 是定稿组件，不要求页面照抄类名；先适配内容，再复用对应参数。

- 黑色是主画布。用低对比的冷蓝紫光和柔和深阴影建立景深。首屏标题背后不放大面积斜置磨砂玻璃板；玻璃质感只用于确有信息承载作用的目录、表头或图示容器。
- 侧栏使用暗蓝半透明层和背景模糊。不要再给侧栏内部叠一个边框明显、底部发亮的独立色块。
- 图示容器使用深色半透明底、细边与节制的光感。保持可读性；不要把整张关系图放在纯白矩形上。
- 中文标题、正文、说明和数字分别设排版层级。正文保持稳定浅色与足够行高。研究页主标题优先用克制的蓝紫渐变；小字不要使用彩虹渐变。
- 视觉应有空间节奏：组内紧凑，组间舒展。不要堆卡片、装饰 Tag 或多余图标。

## 三色表格与图示

- 多张表格按暖橙、蓝、绿循环；第四张回到暖橙。三色来自同一套深色玻璃体系，不改写告警等业务状态色。
- 表格外层承接色彩，圆角约 `24px`。正文保留深色半透明承载层。表头使用对应颜色的半透明磨砂高亮、细亮边和白字。不能只在表格底部放色光而让表头失去区分。
- 关系图和架构图以暖橙、蓝、绿为主要点缀。背景保持深色。同一套流程或能力阶梯中的数字标记统一用蓝紫渐变。01–05 圆标、L0–L4 标签及其连接线或阶梯顶线使用同一色系，不按节点轮换成橙、绿等颜色。
- 对比度优先。文字、数字和链接必须能从光晕及玻璃层中读清。

## 动效边界

角色画面、角色动画与环境动效是三个独立选择。角色形象不是本设计系统的默认组成部分，除非用户明确指定，不自动加入。暗色 Yuki 研究页沿用已确认的雨滴涟漪环境层；其他页面仍以静态为起点。用户要求移除角色画面或动画时，不要推断为移除已确认的雨滴、涟漪或光晕。只保留用户明确指定或该既定风格已有的动效，不让装饰遮挡标题或接收点击。

删除角色、视频或首屏动画后，同时删除它们的固定高度、最小视口高度、占位容器和专属光晕。不要留下空舞台。首屏恢复为正常内容流：标题、解释、核心内容依次出现；组内间距沿用后续章节的节奏。

用户指定“雨滴滴落后晕染开来”时，每屏使用两个错时落点。相邻屏的主要落点在左下与右上交替。先出现短促下落光点，再出现两道扩散波纹和柔和色晕。定稿节奏为约 `9s` 循环，第二个落点错开约 `4.5s`。当前可见表格决定色系，没有表格时默认蓝色。环境层必须 `pointer-events:none`，不能影响阅读和交互。对 `prefers-reduced-motion` 显示静态弱光晕，不运行落下与扩散动画。

## 交付检查

- 检查标题、解释、内容是否各司其职。删除重复句与无意义标签。
- 检查已删除视觉主体是否仍留下 `min-height`、视口高度或不可见占位。首屏不能因历史动画结构产生大块空白。
- 检查桌面与手机的实际渲染、目录锚点、表格、图文比例、文字对比和横向溢出。
- 检查侧栏当前项、抽屉关闭方式、雨滴层点击穿透和低动态模式。
- 检查目标文件和链接确实可打开。若无法目视验证，明确写出未验证项，不把静态检查说成视觉验收。
- 用户指定的内容、配色或其他设计系统优先于本 Skill 的默认样式。修改现有网页时，保留未被要求更改的结构与内容。
